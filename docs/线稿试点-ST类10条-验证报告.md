# 线稿示意 · ST 类 10 条试点验证报告

> 日期 2026-11-05 · 预算上限 1.5 元 · **实际花费 1.44 元**（12 张 × 0.12 元）
> 结论一句话：**风格验证通过（一致性很好），姿态保真度不达批量标准（首过 5/10）**。
> 建议：不要直接铺 100 张，先把控制图从"细线骨架"升级为"有体积的人偶"再复测。

---

## 1. 做了什么

按 `docs/图集三帧出图方案评估.md` §2.4 的"骨架控制 i2i"路线，把线稿生产拆成三段，
前两段（骨架、后处理）完全本地免费，只有中段调 AI：

```
① 参数化骨架（PIL，纯语义手写关节坐标，不依赖照片/MediaPipe）  免费
② seedream i2i / 纯文本直出                                  0.12 元/张
③ 确定性后处理：二值化 + 1px 膨胀 + 双色映射 + 缩到 1080x1440  免费
```

产物：

## 2. 两条路线对照（同姿势 ST-01）

**路线 A：骨架控制 i2i**｜把白底骨架 raster 作为 `image`，AI 只"上风格"
**路线 B：纯文本直出**｜不给控制图，姿势全靠提示词描述

| 维度 | A（骨架控制） | B（纯文本） |
| --- | --- | --- |
| 姿态是否等于设计值 | ✅ 基本一致（站直、双臂略离体） | ❌ **自行改成行走姿势**，一步迈出、身体转 3/4 |
| 身体结构可见度 | ✅ 贴身练功服，关节与肌肉线清楚 | ❌ 毛衣＋牛仔裤＋靴，**衣服把身体结构盖住了** |
| 关节圆点 | 落在关节附近（大小有漂移） | 落在衣服上，语义失效 |
| 风格可用度 | ✅ 杂志风时装速写，干净 | ✅ 也好看，但更像"穿搭插画" |
| 可控性 | 中（腿、头附近的手都稳） | **低**（模型自由发挥） |
| 单张成本 | 0.12 元 | 0.12 元 |

**推荐路线 A。** 线稿帧的教学价值在"关节角＋重心＋四肢走向"，B 把姿势改掉了、还用
衣服遮掉结构，语义直接失效；A 虽然也会走形，但至少"错在可控范围内"。

## 3. 姿态保真度实测（本轮最重要的发现）

逐条比对骨架与出图（证据：`_pose-audit.png`）：

| ID | 姿势 | 判定 | 说明 |
| --- | --- | --- | --- |
| ST-01 | 自然直立 | ✅ | 双臂比骨架更贴近躯干，但整体正确 |
| ST-02 | 45° 侧身回眸 | ✅ | 手到发际成功了 |
| ST-03 | 靠墙站 | ⚠️ 偏弱 | 屈膝在，但"靠墙"没体现，图幅偏小 |
| ST-04 | 双手插袋 | ❌ | 双手被拉到身前合拢，不是插袋 |
| ST-05 | 松弛环抱 | ❌ | **交叉手臂被整体抹平**，变成自然下垂 |
| ST-06 | 拨发动态 | ✅ | 手到发际 |
| ST-07 | 提裙旋转 | ❌ | **双臂侧张被收回身侧**（已花 0.12 元做文字补强，仍失败） |
| ST-08 | 俏皮后勾腿 | ✅ | 后勾腿准确 |
| ST-09 | 踮脚伸展 | ❌ | **上举手臂被放下**，双臂都变下垂 |
| ST-10 | 逆光剪影 | ✅ | 一臂外伸＋一腿侧踢都保住 |

**首过率 5/10（50%），偏弱 1，失败 4。** 比 §2.2 的先验（站姿 0.60–0.70）还低一档，
因为细线骨架携带的体量信息比"照片描边"更少。

### 失败规律（可直接指导排产）

| 姿势类型 | 首过 | 结论 |
| --- | --- | --- |
| **正面视角** + 四肢大幅外展（ST-08/10） | 高 | 腿的动作最稳，几乎不掉 |
| **手在头附近**（ST-02/06） | 高 | 有"天然锚点"，模型不会乱动 |
| **手臂贴近或横跨躯干**（ST-04 插袋 / ST-05 交叉） | 低 | 被合并进躯干轮廓，抹平 |
| **侧面 / 近侧面视角**（ST-03/09） | 低 | 侧视投影信息少，模型倾向"扶正"成正面下垂 |

失败全部发生在**手臂**上；**腿、头、手到发**几乎不失败。这与 §2.3 预判的失效模式
（"手臂并入躯干、屈膝拉直"）一致，但"屈膝拉直"本轮没发生，**手臂问题比预期更严重**。

### 文字补强无效（已花 0.12 元验证）

对 ST-07 追加显式文本："双臂向身体两侧张开并远离躯干，肘部略弯……不得自行美化或修正姿态"。
结果**手臂仍然下垂**，与不补强几乎无差别（`images/lineart/fix/`）。
→ 结论：在 flash 档模型上，"图像控制的姿态"压不过"审美先验"，**靠加字救不回来**。

## 4. 风格一致性（AI 的强项，超出预期）

后处理是风格兜底的关键：把每张 AI 图的灰阶/线宽/底色差异**压平**成同一套调色板后，
10 张摆在一起像同一个人画的 —— 这正是 §2.1 判定"不满足"的那一项。

| 指标 | 结果 |
| --- | --- |
| 尺寸 | 10/10 = 1080×1440（3:4，与封面卡片对齐） |
| 体积 | 10/10 ≤ 20KB，均值 **16.0KB**，合计 160.1KB，最大 18.1KB |
| 配色 | 强制双色：墨线 `#3B3630` / 底 `#F6F0E5` |
| 反差 | 线宽统一（二值化 + 1px 膨胀） |

调色板归一化前后对比与膨胀档位（`trial/_cmp-weight.png`）：膨胀 0 太细会断线，
**膨胀 1 最佳**，膨胀 2 会让五官糊成块。

## 5. 锚定参数（复跑用）

```yaml
通道: arkcli api arkruntime.generate_images        # raw action，模型名直调
  profile: platform_cn-beijing_accountwide
  # 本账号 platform 数据面只认 raw action；无 EP，+gen 传模型名会被客户端拦截
模型: doubao-seedream-5-0-flash-260915             # 0.12 元/张
size: 1728x2304       # 3:4，3.98M 像素（在模型下限之上），落地再缩到 1080x1440
watermark: false
output_format: jpeg
response_format: url  # URL 24h 过期，拿到立即 curl（系统 python urllib 缺 CA 会 SSL 失败）
seed: md5(POSE-ID)[:8] % 2^31                      # 全库统一策略，可复现
image: data:image/png;base64,...                   # 路线 A：1728x2304 白底骨架控制图
```

**定版提示词（224 字，路线 A）**

```
将参考图中的人体骨架示意图重绘为杂志风时装速写线稿：单色深炭灰墨线，线条粗细均匀、
收笔利落，在骨架基础上补出完整人体轮廓与主要结构线，不画阴影、不画排线、不画面料纹理，
纯白背景，关节处保留实心小圆点，人物为年轻女性，穿贴身纯色连体练功服、线条简洁的平底鞋，
发型简洁，全身姿态与参考图完全一致，竖构图，头顶与脚下留白，人物居中，全身完整入画不裁切。
画面避免：灰阶过渡、铅笔颗粒、文字、数字、标注、箭头、边框、多余线条、背景环境、道具、外套、图案花纹。
```

> 说明：`穿贴身纯色连体练功服` 这句是把 ST-01 试跑**意外产出**的服装锁死的结果。
> 原提示词没写服装，模型自己套了连体服；因为连体服恰好最利于"看结构"，就把它固化进模板。
> 该通道**没有独立负向词参数**，只能内联"画面避免……"。

**后处理（必做，确定性）**

```
1728x2304 → 居中裁 3:4 → LANCZOS 缩到 1080x1440
→ 灰度 + 99 分位白平衡 → 二值化(t1=150, t2=232) → 去孤点(<5px)
→ 1px 膨胀 → 映射 {墨线 #3B3630, 底 #F6F0E5} → PNG optimize
```

## 6. 成本与对 12 元预算的影响

| 项 | 金额 |
| --- | --- |
| 路线 A/B 对照试跑 2 张 | 0.24 元 |
| ST-01（试跑那张直接采用） | 0.00（含在上行） |
| ST-02..ST-10 共 9 张 | 1.08 元 |
| ST-07 文字补强验证 1 张 | 0.12 元 |
| **合计** | **1.44 元**（预算 1.5，余 0.06） |

**对全量的推演（关键风险）**：按本轮 50% 首过率，100 张需约 140 次调用 ≈ **16.8 元，超 12 元预算 40%**。
即使只对失败的 40 张做 1 次重试，也要 140 次。要落进 12 元，只有三条路：

1. **提高首过率**（推荐）：控制图从"细线骨架"改成"有体积的人偶"（躯干/四肢画成锥形柱体、
   头画成椭球），让模型读到体量而不是几根线；预计能把手臂类失败拉回来一半。
2. **失败即回落到矢量骨架**（零成本）：AI 成功的 6 成用风格化图，失败 4 成用
   `skeleton/ST-xx.svg`（930B，姿态 100% 正确）。代价是一套图里两种画风。
3. **只在"正面 + 四肢外展"类姿势用 AI**，侧面/贴近躯干类直接出矢量。

## 7. 结论与下一步建议

**已验证（可复用）**
- 骨架 → seedream i2i → 确定性后处理的管线跑通了，单张 0.12 元、端到端约 15 秒。
- 后处理能把风格一致性做到 §2.1 要求的水准（10/10 尺寸达标、均值 16KB）。
- 参数化骨架不依赖 MediaPipe/cv2，纯手写坐标即可出图 —— 绕开了本机装不上库的问题。

**未达标（必须先解决再做全量）**
- 姿态保真度 50%，且失败集中在手臂；**加文字补强无效**（已实测）。
- 侧面/近侧面视角明显更差。

**建议下一步（≤1.5 元可验证）**
1. 把骨架改成"有体积人偶"控制图，用 ST-04 / ST-05 / ST-09 三条（本轮全败的）复测，
   3 张 = 0.36 元。若这 3 条能过，说明问题在控制图而非模型，再谈铺全量。
2. 若仍是 50%，就别走 AI 线稿了 —— 直接用 `skeleton/` 下的矢量套（930B/张、姿态 100% 正确、
   零成本、可无限缩放），把省下的 12 元投到示例图的摄影质量上。

**给全量批次的两条硬建议**
- 关节圆点建议从 AI 出图里去掉，改由 App 的标注层（SVG）绘制，否则 100 张圆点大小/位置都要漂。
- `docs/图集三帧出图方案评估.md` §2.5 的结论仍然成立：CLOSE/POV 那 ~20 条语义上不该给人体线稿。
